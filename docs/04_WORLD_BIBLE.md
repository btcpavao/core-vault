# Core Vault — World Bible

**Document:** 04 / World Foundation  
**Status:** Foundational World Specification  
**Depends on:**  
- `01_VISION_AND_PHILOSOPHY.md`

- `03_TECHNICAL_ARCHITECTURE.md`

**Applies to:** World design, spatial continuity, environment architecture, recurring artefacts, visual semantics, environmental storytelling, room relationships, object families, world-state representation, atmosphere, and all future Core Vault environments.

---

# 1. Purpose of This Document

This document defines the world in which Core Vault exists.

It establishes:

- what kind of place Core Vault is
- how the environment is spatially organized
- what physical and technological rules govern the world
- which objects recur across rooms
- how Bitcoin concepts become environmental objects
- how different rooms remain visually and conceptually connected
- what the environment may imply
- what it must never imply

This is not a detailed room specification.

`05_ROOM_DESIGN.md` defines each individual room in detail.

This document defines the **shared world those rooms belong to**.

---

# 2. Core Vault Is One Place

Core Vault must feel like one coherent facility.

The Main Hall, Workshop, Archive, Engine Room, Observatory, Communications, Library, and Vault Chambers are not independent visual themes.

They are different parts of the same physical environment.

The user should gradually develop a mental map of the facility.

The world must communicate:

> “These rooms belong to one place.”

Not:

> “These are separate application screens created by different designers.”

---

# 3. The Facility

The Core Vault environment is best understood as a private Mediterranean technological sanctuary built around the user's Bitcoin infrastructure.

It is not literally a historical building.

It is not literally a bank.

It is not literally a laboratory.

It is not literally a temple.

It combines selected qualities from each without becoming any of them.

The facility feels:

- permanent
- private
- deliberately constructed
- technologically advanced
- naturally integrated into its landscape
- quiet
- self-contained
- owned by the user

It exists conceptually at the intersection of:

**Mediterranean architecture + precision engineering + sovereign Bitcoin infrastructure.**

---

# 4. The User Owns the Place

Core Vault should not feel like a corporate headquarters the user is visiting.

It should not feel like a financial institution granting access.

It should not feel like someone else's server room.

The emotional premise is:

> **This facility belongs to the user.**

Their node runs here.

Their vaults exist here.

Their keys have meaning here.

Their backups are preserved here.

There is no teller.

There is no administrator.

There is no institution standing between the user and Bitcoin Core.

---

# 5. No Visible Avatar

The user does not control a visible character.

There is no:

- player model
- body
- hand animation requirement
- character customization
- third-person representation

The user's point of view is the human presence in the environment.

Core Vault should create presence through:

- camera
- scale
- sound
- perspective
- object response
- spatial continuity

not through an avatar.

---

# 6. The Camera Represents Presence

The camera should feel approximately human in scale.

Objects should therefore be designed so their dimensions make intuitive sense relative to a person standing in the environment.

A vault should feel substantial.

A key artefact should feel like something that could plausibly be handled.

The Core reactor should feel like machinery larger than the user.

Architecture should provide believable:

- doors
- stairs
- platforms
- railings
- tables
- alcoves
- corridors
- viewing positions

even when not every element is physically traversable.

---

# 7. The World Is Curated, Not Freely Explorable

Core Vault is not an open-world game.

The facility is carefully staged.

The user experiences a sequence of designed viewpoints and transitions.

Spaces may visually suggest far greater architectural scale than is actually navigable.

This is intentional.

The world should feel larger than the application's functional footprint without requiring a complete explorable building.

---

# 8. Geographic Identity

The facility exists in a Mediterranean coastal environment.

The exact real-world country or city should remain undefined.

Do not explicitly establish:

- Croatia
- Greece
- Italy
- Spain
- a fictional named nation

The design should instead combine broad Mediterranean qualities.

This allows the place to feel recognizable without becoming geographically literal.

---

# 9. Relationship With the Sea

The sea is an important environmental motif.

It represents:

- openness
- time
- continuity
- calm
- horizon
- scale beyond the facility

The sea should be visible only where compositionally appropriate.

It should not appear through every window merely to reinforce branding.

Particularly appropriate spaces include:

- Main Hall
- Observatory
- selected corridors
- possibly Library terraces
- transitional spaces

The Engine Room may feel deeper and more enclosed.

The Archive may have almost no direct exterior exposure.

---

# 10. Landscape

The surrounding landscape should be restrained.

Possible distant elements:

- rocky Mediterranean coast
- pale cliffs
- low vegetation
- cypress-like silhouettes
- olive-like vegetation
- distant hills
- calm sea
- open sky

Avoid creating a lush tropical resort.

Avoid tourism imagery.

The setting is architectural and contemplative, not vacation-oriented.

---

# 11. Architecture

The architecture should use large, simple structural forms.

Primary forms include:

- arches
- thick stone walls
- broad steps
- terraces
- deep openings
- vaulted ceilings
- columns used sparingly
- recessed alcoves
- stone platforms
- courtyards
- restrained geometric cuts

The architecture should feel constructed to last for centuries.

---

# 12. No Historical Reconstruction

The facility is not intended to reproduce Roman, Greek, Renaissance, Venetian, or any other historical architecture.

Avoid:

- classical statues
- ornate Corinthian columns
- mosaics used as historical decoration
- frescoes
- coats of arms
- medieval symbolism
- religious iconography

Mediterranean influence should come from:

- material
- light
- proportion
- openness
- stone construction
- relationship to landscape

rather than historical costume.

---

# 13. Architecture and Technology Are Integrated

Technology should not appear to have been placed inside an old building after the fact.

The facility was conceptually designed around its technology.

Therefore:

- conduits may run inside carved stone channels
- glass energy systems may emerge naturally from architectural bases
- bronze frames may be structurally embedded
- reactors may sit inside purpose-built circular chambers
- vaults may occupy architectural niches specifically designed for them

The technology and architecture should feel mutually designed.

---

# 14. Technology Is Physical

Core Vault technology should appear tangible.

Avoid environments dominated by floating holographic screens.

Technology is represented primarily through:

- mechanisms
- rings
- chambers
- glass vessels
- precision metal assemblies
- channels
- conduits
- lenses
- articulated structures
- controlled energy

Screens and contextual displays may exist when information requires them, but they should not define the visual world.

---

# 15. No Server-Rack Aesthetic

The Engine Room is not a conventional datacenter.

Avoid:

- rows of server racks
- blinking Ethernet switches
- rack-mounted machines
- cooling fans everywhere
- cable spaghetti
- generic industrial IT equipment

Bitcoin Core is visualized semantically, not literally reconstructed as PC hardware.

---

# 16. Technology Is Precise, Not Magical

The environment may feel extraordinary.

It must not feel supernatural.

Avoid effects that imply:

- magic
- spells
- mystical forces
- divine energy
- supernatural artefacts

Blue and gold energy are visual abstractions of computation, connectivity, authorization, and system activity.

They are not magic.

---

# 17. No Fictional Technology Explanations

The world should not invent fictional scientific explanations for Bitcoin.

Do not claim:

> “Quantum energy flows through the cryptographic core.”

Do not invent lore explaining Bitcoin technology through fictional machinery.

The environment is metaphorical.

Technical explanations in the Library or contextual information must refer to real Bitcoin concepts.

---

# 18. Environmental Storytelling Without Fictional Story

The facility may imply function and history through:

- wear
- composition
- empty spaces
- repeated objects
- architecture
- activity
- lighting

But Core Vault does not require fictional narrative lore.

There is no need to establish:

- who built the facility
- ancient civilizations
- a future timeline
- fictional companies
- named engineers
- wars
- characters

The user's Bitcoin activity is the story.

---

# 19. Primary Material: Limestone

Warm Mediterranean limestone is the dominant architectural material.

Characteristics:

- warm ivory
- pale beige
- subtle natural variation
- matte surface
- soft edge wear
- believable pores and imperfections

It should feel substantial without appearing dirty or ruined.

---

# 20. Stone Must Not Feel Ancient and Broken

Avoid:

- crumbling walls
- excessive cracks
- ruins
- moss-covered stone
- abandoned atmosphere
- archaeological decay

The facility is maintained.

It is timeless, not ancient and neglected.

---

# 21. Primary Metal: Bronze

Bronze is the primary structural technology metal.

It may be used for:

- frames
- rings
- hinges
- mechanisms
- rails
- mounts
- key artefacts
- vault structures

Bronze creates continuity between:

- architectural warmth
- technological precision
- gold energy

It should generally be refined rather than ornamental.

---

# 22. Secondary Metals

Other metals may include:

- brushed dark metal
- warm gold-toned alloy
- subtle steel
- near-black structural metal

Use them sparingly.

Chrome-heavy futuristic aesthetics should be avoided.

---

# 23. Glass

Glass represents:

- visibility into mechanisms
- transparency
- containment
- precision
- controlled energy

Appropriate uses:

- reactor chambers
- backup capsules
- energy tubes
- communication terminals
- observation mechanisms
- selected railings or barriers

Glass should feel physically present.

It should not become generic UI glassmorphism.

---

# 24. Energy as a World Material

Energy is treated almost like another material.

It may:

- flow
- pulse
- collect
- connect
- activate
- fade
- travel between mechanisms

Energy should remain constrained by architecture and machinery.

It generally travels through:

- channels
- conduits
- cores
- rings
- glass tubes
- engraved pathways

Avoid random free-floating neon lines.

---

# 25. Blue Energy

At the world-bible level, blue energy represents broadly:

- computation
- information
- active system processes
- network flow
- Bitcoin infrastructure activity

Exact semantic assignments will be refined in `08_ART_DIRECTION.md`.

Blue should feel:

- cool
- clean
- precise
- stable
- technological

Not aggressive.

---

# 26. Gold Energy

At the world-bible level, gold energy represents broadly:

- authorization
- validated completion
- protected value
- trusted state
- completed activation

Gold should not automatically mean:

- wealth
- high balance
- financial prestige

This distinction is critical.

Gold represents **meaningful validated state**, not “more money.”

---

# 27. Blue and Gold Together

Blue and gold may interact during important operations.

Examples:

- a signing authority activates
- a vault policy progresses
- a Core operation completes
- a backup seals

Their interaction can visually represent:

> system activity + validated authorization

But avoid using both colors everywhere.

Their combination should remain significant.

---

# 28. Energy Does Not Represent Bitcoin Amount

Never increase:

- energy brightness
- reactor size
- glow intensity
- number of particles
- vault grandeur

based on bitcoin balance.

A vault containing 5,000 sats and one containing 10 BTC use the same world language.

This prevents wealth gamification.

---

# 29. Recurring Artefact Family: Vault

The Vault is one of the central objects of the world.

A Vault represents:

- one logical Core Vault wallet
- its spending policy
- its relationship with keys

The Vault should appear physically robust and technologically precise.

It should not resemble:

- a bank safe from a western
- a household safe
- a cartoon treasure chest

---

# 30. Vault Design Language

A Vault may combine:

- carved or machined stone
- bronze structure
- glass internal components
- circular mechanisms
- key interfaces
- controlled blue/gold energy

The mechanism itself should visually communicate spending structure.

For example:

single-sig:

> one meaningful authorization path

multisig:

> several independent authorization paths converging on a common mechanism

---

# 31. Vaults Should Be Recognizable Across Rooms

The same logical Vault may appear:

- in the Main Hall
- in its Vault Chamber
- in the Workshop during construction
- indirectly in the Archive
- indirectly in Communications

Its visual identity should remain recognizable.

This may include:

- silhouette
- central core pattern
- identifying engraving
- subtle unique pattern

---

# 32. Recurring Artefact Family: Keys

A Core Vault key represents signing authority.

It does not necessarily represent one literal physical key-shaped object in the real world.

The artefact is a human-readable visual representation of authorization.

---

# 33. Key Visual Language

Keys should feel:

- compact
- precise
- physically important
- high-tech
- individually identifiable

Possible form language:

- elongated geometric artefact
- bronze/gold chassis
- central glass core
- internal energy
- activation ring
- connector structure

Avoid literal house-key teeth unless used extremely abstractly.

---

# 34. Key States

A key should support visually distinct semantic states:

- inactive
- available
- selected
- signing
- signed
- unavailable
- warning
- error

The exact visual implementation is defined later.

The important world rule is:

> A key's state should feel like a physical state change, not merely an icon changing color.

---

# 35. Key Identity

Different keys belonging to one vault must be distinguishable.

Do not primarily distinguish them through:

- rarity
- luxury
- stronger glow

Use stable identifiers such as:

- engraved pattern
- shape variation
- ring pattern
- user label
- subtle material marker

---

# 36. Recurring Artefact Family: Backup Capsule

The Backup Capsule represents a real Bitcoin Core wallet backup.

It should communicate:

- preservation
- containment
- integrity
- recoverability

The capsule must remain conceptually tied to a real file.

---

# 37. Backup Capsule States

Possible semantic states:

- empty
- preparing
- writing
- sealed
- verification pending
- verified
- warning
- failed

A sealed capsule means a real backup operation succeeded.

A verified state means the defined verification process succeeded.

Never imply physical redundancy the application cannot know about.

---

# 38. Recurring Artefact Family: Core Reactor

The Core Reactor is the main environmental representation of Bitcoin Core.

It lives primarily in the Engine Room but may have echoes elsewhere through conduits and system state.

The Core Reactor represents:

- Bitcoin Core process availability
- synchronization
- network activity
- broad node health

---

# 39. Core Reactor Is the Heart of the Facility

Conceptually, the facility's technological systems originate from the Core Reactor.

This provides a useful spatial metaphor:

Bitcoin Core powers the application.

Conduits may visually connect the Engine Room to:

- Communications
- Observatory
- Main Hall status infrastructure

This should not imply that Bitcoin Core literally supplies electrical energy.

It is environmental metaphor.

---

# 40. Reactor State Must Be Truthful

The Reactor cannot visually appear fully operational if Core is unavailable.

Broad states include:

- dormant
- connecting
- synchronizing
- stable
- network-isolated
- warning
- error

Specific visuals will be defined later.

---

# 41. Recurring Artefact Family: Conduits

Conduits represent system relationships and flow.

They may appear as:

- glass tubes
- illuminated channels
- embedded floor lines
- architectural grooves
- suspended controlled channels

Conduits may represent:

- network activity
- information flow
- authorization flow
- system linkage

They should not become decorative spaghetti.

---

# 42. Conduits Establish World Continuity

A conduit visible leaving one space may appear to continue elsewhere.

For example:

Engine Room external conduits may visually imply connection toward Communications and Observatory.

This helps rooms feel physically related.

---

# 43. Recurring Artefact Family: Communication Terminal

Communication terminals represent exchange between a vault and Bitcoin network processes.

They may support:

- Receive
- Send
- PSBT import/export
- Broadcast

The terminal should look like physical infrastructure integrated into the room.

---

# 44. Recurring Artefact Family: Time Mechanism

A future time mechanism may represent:

- relative timelock
- absolute timelock
- recovery delay

Possible form language:

- precision clockwork
- concentric rings
- suspended timing core
- glass chronometer

Avoid literal fantasy hourglasses as the only representation.

An hourglass motif may influence the design abstractly.

---

# 45. Time Mechanisms Must Not Exist as Fake Functionality

If timelock functionality is not technically implemented, the world may hint at future capability only if clearly unavailable.

Do not let users interact with a convincing operational time artefact that does not compile to a real spending policy.

---

# 46. Recurring Artefact Family: Policy Branches

Taproot and future script-policy structures may eventually appear as branching physical or light structures.

A policy branch may be represented through:

- branching energy paths
- glass conduits
- bronze branching structures
- luminous paths

But every displayed branch must correspond to real policy semantics when used functionally.

---

# 47. The Facility's Spatial Topology

The facility should have a stable conceptual topology.

The exact camera implementation may differ, but room relationships should remain consistent.

Canonical conceptual structure:

```text
                         OBSERVATORY
                              │
                              │
                          MAIN HALL
                    ┌─────────┼─────────┐
                    │         │         │
                 LIBRARY   VAULTS    WORKSHOP
                    │         │         │
                    │         │         │
                  ARCHIVE  COMMUNICATIONS
                              │
                              │
                         ENGINE ROOM
```

This diagram represents conceptual relationships, not exact floorplan geometry.

---

# 48. Main Hall as Geographic Center

The Main Hall is the primary orientation point.

From there the user should intuitively perceive pathways toward major areas.

It is the world's geographic and conceptual center.

Frequent tasks should not require returning to Main Hall after every operation.

But it remains the stable home location.

---

# 49. Engine Room as Structural Foundation

The Engine Room should feel physically deeper in the facility.

This supports the metaphor:

> The engine runs underneath everything.

Possible architectural cues:

- descending stairs
- deeper stone
- heavier structure
- reduced exterior light
- stronger technological illumination

It should not feel like a basement dungeon.

---

# 50. Observatory as Outward-Facing Space

The Observatory should feel positioned toward the exterior edge of the facility.

It looks outward.

This matches its function:

> observing Bitcoin activity beyond the immediate vault environment.

It should have the strongest relationship to:

- horizon
- sky
- distant light
- sea

---

# 51. Archive as Inward-Facing Space

The Archive should feel protected within the facility.

Possible cues:

- thick walls
- fewer exterior openings
- controlled lighting
- repeated protected niches
- calm acoustic character

It should not feel oppressive.

The feeling is preservation, not imprisonment.

---

# 52. Workshop as Active Craft Space

The Workshop may have more open space around its central work surface.

It should feel like:

- precision
- construction
- deliberate assembly

It may have stronger visible mechanical detail than the Main Hall or Library.

---

# 53. Library as Quiet Space

The Library should feel:

- slower
- warmer
- quieter
- texturally softer

It may use:

- stone
- darker wood in limited amounts
- bronze
- glass knowledge artefacts
- controlled natural light

It remains technologically integrated.

---

# 54. Communications as Threshold Space

Communications sits conceptually between:

- vault
- node
- external Bitcoin network

It should therefore feel like a threshold or transfer space.

It may visually emphasize:

- directional conduits
- transmission channels
- controlled gateways
- incoming/outgoing flow

---

# 55. Vault Chambers Form a Secure Wing

Individual Vault Chambers may conceptually occupy a dedicated area branching from the Main Hall.

The user does not need to navigate a literal hallway containing dozens of rooms.

The system may abstract this spatially.

But vaults should feel like persistent places rather than temporary modal screens.

---

# 56. Scale

The facility should feel larger than an ordinary home but smaller and more intimate than a monumental public institution.

Ideal emotional scale:

> private architectural complex

Not:

> enormous megacity

Not:

> tiny personal office

Not:

> palace

The environment should feel substantial because Bitcoin matters, but still personally owned.

---

# 57. Repetition and Rhythm

Architectural repetition may create world consistency.

Examples:

- recurring arch proportions
- circular bronze mechanisms
- specific glass curvature
- carved conduit channels
- repeated stone joint patterns
- signature railings
- repeated light fixture logic

Use repetition intentionally.

---

# 58. Avoid Excessive Ornament

The facility does not need decoration for decoration's sake.

Avoid:

- patterns everywhere
- ornamental carvings
- decorative statues
- luxury objects
- trophies
- branding everywhere

Functional mechanisms themselves provide visual interest.

---

# 59. Core Vault Branding Inside the World

Branding should be subtle.

Possible use:

- small mark at entry
- engraved emblem
- About panel
- startup presentation

Avoid placing “CORE VAULT” on every wall and device.

The facility should feel real enough not to require constant branding.

---

# 60. Bitcoin Branding

Use the Bitcoin symbol carefully.

The world should not resemble branded merchandise.

Appropriate uses may include:

- subtle system identity
- Library content
- startup or About
- selected engravings

Avoid large orange Bitcoin logos throughout the facility.

The application's Bitcoin identity should emerge through function.

---

# 61. No Orange-Dominated Crypto Aesthetic

Bitcoin orange may exist as a limited informational or brand accent.

It is not a major environmental material.

The primary world identity remains:

- limestone
- bronze
- glass
- blue
- gold
- Mediterranean natural light

---

# 62. World Lighting Logic

Every light source should appear to have plausible origin.

Examples:

- sunlight through openings
- reactor emission
- conduit light
- integrated architectural fixtures
- reflected sea/sky light

Avoid random glow without source.

This is essential for realism.

---

# 63. Natural Light and Technological Light

A key visual contrast is:

**natural warm Mediterranean light**

against

**cool precise technological light.**

Gold energy acts as a bridge between these systems.

This tension should appear throughout the world.

---

# 64. Exterior Light

Exterior daylight should generally feel:

- warm
- soft
- directional
- Mediterranean
- breathable

Avoid overly dramatic apocalyptic skies.

The outside world is calm.

---

# 65. Night Mode as a Future Possibility

A future version may allow world lighting to shift with time of day.

This is not foundational functionality.

If implemented later:

- it must remain readable
- it must not obscure system state
- night mode should remain calm rather than cyberpunk

---

# 66. Weather

Dynamic weather is not required.

If weather exists later, keep it subtle.

Suitable:

- clear day
- light cloud
- gentle distant rain

Unsuitable:

- dramatic storms during transaction signing
- weather used as financial metaphor
- emotional manipulation based on wallet state

---

# 67. Environmental Motion

The facility should never be fully frozen.

Possible ambient movement includes:

- sunlight shift
- ocean motion
- dust
- curtain movement
- distant foliage
- subtle mechanical rotation
- energy flow
- reflections

Movement should remain sparse.

---

# 68. World Breathing

Every room should contain enough micro-motion that the environment feels alive.

A useful rule:

> If the user watches a room for thirty seconds without interacting, they should notice a few small changes.

But those changes should never compete for attention.

---

# 69. No Idle Spectacle

The world does not perform for the user.

Avoid:

- large random machine activations
- unexplained energy explosions
- constant large mechanical movements
- cinematic events without state change

Ambient life is restrained.

---

# 70. New Block as a World Event

A new block is one of the rare Bitcoin events that may subtly propagate through multiple spaces.

Possible responses:

Engine Room:
- short reactor pulse

Observatory:
- visible block event

Main Hall:
- almost imperceptible energy response

Communications:
- optional subtle channel pulse

Do not trigger a full facility light show.

---

# 71. Synchronization as Environmental State

When Bitcoin Core is synchronizing, the facility should feel functional but not fully settled.

The world should not appear broken.

Potential broad cues:

- Reactor has measured progress
- some network flow is active
- certain information surfaces indicate incomplete chain state

Avoid making every room flash “SYNCING.”

---

# 72. Core Disconnection

When Core becomes unavailable:

- the facility remains physically present
- Bitcoin-dependent systems lose active energy
- the Reactor becomes dormant or unavailable
- affected objects communicate restricted functionality

The entire application should not visually collapse.

The world exists even when its engine is unavailable.

---

# 73. Network Disabled

When Bitcoin Core network activity is deliberately disabled:

- Core Reactor remains alive
- local mechanisms remain functional
- external conduits become inactive
- offline signing remains visually intentional

This state must feel:

> isolated by choice

not:

> broken.

---

# 74. Error States

Errors should influence relevant objects locally.

Example:

backup fails:
- affected capsule does not seal
- restrained warning state appears

signing fails:
- selected key stops its signing transition
- warning state appears

Do not turn the entire room red.

---

# 75. World Soundscape

The facility's soundscape is environmental rather than musical.

Global sound families:

- distant sea
- wind
- architectural room tone
- soft mechanical resonance
- controlled energy hum
- material interaction

Each room uses different proportions.

---

# 76. Acoustic Continuity

Rooms should sound related.

For example:

the underlying distant Core system hum may be barely perceptible throughout some sections of the facility and stronger in the Engine Room.

The sea may become more audible toward the Observatory.

This helps spatial continuity.

---

# 77. No Constant Musical Score

Music should not be required for atmosphere.

If future versions introduce musical ambience, it should:

- be extremely subtle
- contain no recognizable melody loop that becomes tiring
- be optional
- remain secondary to environmental sound

Core Vault should still feel complete when music is disabled.

---

# 78. Interaction Sound Family

Artefact sounds should share a coherent material vocabulary.

Possible elements:

- ceramic-like resonance
- glass harmonic
- precision metal click
- low mechanical engagement
- soft energy tone

Avoid:

- arcade bleeps
- generic sci-fi laser sounds
- mobile notification sounds

---

# 79. Physicality

Interactions should have subtle physical weight.

Examples:

a key seating into position should not feel like dragging a flat icon.

A capsule sealing should feel mechanically real.

A reactor ring changing mode should have momentum.

Use:

- acceleration
- deceleration
- mechanical timing
- sound
- light response

to create believable physicality.

---

# 80. No Exaggerated Physics

Core Vault does not need realistic loose-body simulation.

Objects generally follow designed animations.

Do not let important artefacts:

- bounce
- fall off tables
- collide unpredictably
- spin freely

The environment is precise.

---

# 81. Object Resting State

Important objects should look composed even while idle.

The scene should not depend on animation to make an artefact interesting.

Good modelling, material, silhouette, and light should carry the resting state.

---

# 82. Human Scale Through Familiar Architecture

Even though technology is unfamiliar, the architecture provides recognizable scale.

Use believable:

- table heights
- door dimensions
- steps
- seating surfaces if any
- railings
- hand-level mechanisms

This grounds the advanced technology.

---

# 83. Do Not Fill Rooms With Screens

If every wall contains displays, Core Vault becomes a control room instead of a spatial interface.

Textual information should emerge contextually.

Screens should be rare and purposeful.

---

# 84. Contextual Displays Belong to Artefacts

When conventional UI appears, it should feel associated with a physical object.

For example:

- panel emerging near communication terminal
- technical details projected beside Reactor
- backup file details appearing when capsule is inspected

This maintains world continuity.

---

# 85. Environmental Labels

Room and object labels may appear:

- engraved
- projected
- subtly floating near focus state
- as DOM overlays

Avoid permanently floating labels above every object.

The world should remain visually calm.

---

# 86. World Navigation Cues

The facility should use environmental cues to indicate navigable paths.

Possible cues:

- brighter opening
- visible destination object
- floor conduit
- architectural framing
- shallow focus response
- minimal text
- sound shift

Avoid giant glowing arrows.

---

# 87. Main Hall Should Reveal the World Gradually

The Main Hall should not display every room as an equal menu option.

Its composition should suggest hierarchy.

For example:

- vault area may dominate
- Workshop may be clearly accessible
- Engine Room may be visually implied below
- Observatory may draw the eye toward exterior light
- Library may occupy a quieter side

This is spatial design, not menu design.

---

# 88. Locked Future Areas

Future functionality may be represented by physically present but inactive areas only when useful.

For example:

a future advanced policy section of the Workshop may exist behind an inactive mechanism.

If used:

- clearly indicate it is unavailable
- do not make it resemble a puzzle
- do not frustrate the user with fake interactivity

---

# 89. No Easter Eggs That Affect Bitcoin

Non-functional visual Easter eggs may exist eventually.

They must never:

- unlock financial functionality
- change wallet state
- hide important controls
- affect security

This is not a game economy.

---

# 90. No NPCs

The facility should initially contain no non-player characters.

There is no:

- guide character
- banker
- robot assistant
- security guard
- AI avatar

Onboarding comes from:

- environment
- text
- optional guidance

The facility remains private and quiet.

---

# 91. No Social Space

Core Vault is not a multiplayer lobby.

Avoid introducing:

- public profiles
- friends
- visible other users
- avatars
- chat

The user's relationship is with their own Bitcoin infrastructure.

---

# 92. Privacy Is Visible Through Absence

The world should feel private because nothing unnecessary is present.

No:

- advertising
- news tickers
- market data
- social feeds
- remote account status
- promotions

The absence itself reinforces ownership and calm.

---

# 93. World Persistence

The facility should feel persistent across sessions.

When the user returns:

- vaults are where they expect
- room structure is familiar
- named artefacts retain identity
- backup state is reflected
- environmental preferences persist

Do not randomly rearrange the world.

---

# 94. Persistent Architecture, Dynamic State

Architecture is largely stable.

System state changes.

This gives the user:

- orientation through stability
- information through change

Do not dynamically regenerate room layouts based on state.

---

# 95. Vault Growth

If the user creates many vaults, the world must scale without turning the Main Hall into clutter.

Potential future solutions:

- expandable vault gallery
- dedicated secure wing
- curated paging through chambers
- architectural segmentation

Do not simply place fifty vault models in one room.

---

# 96. World Does Not Mirror Filesystem

The physical organization of the facility should not mirror:

- Core wallet directory names
- file paths
- internal databases

The world organizes concepts according to human meaning.

Technical mapping remains discoverable separately.

---

# 97. The World Is an Interpretive Layer

Core Vault's environment is an interpretation of Bitcoin concepts.

It should make those concepts easier to reason about.

The goal is not literal representation.

For example:

Bitcoin signatures do not physically flow through gold tubes.

But visualizing authorization moving from keys toward a vault may improve understanding.

That is valid if the metaphor remains truthful.

---

# 98. Never Over-Interpret Data

Do not infer emotional meaning from technical state.

Example:

Large mempool does not mean the Observatory becomes stormy.

Low balance does not mean the Vault becomes dark.

High fees do not make the environment dangerous-looking.

The environment represents state, not narrative judgment.

---

# 99. Mempool World Language

Mempool visualization may use:

- controlled particles
- light density
- flowing data-like material
- contained reservoir

It should communicate:

- volume
- activity
- movement

not individual transaction “coins.”

---

# 100. Blocks World Language

Blocks may be represented as:

- stable formed structures
- pulses
- solidified information objects
- discrete rhythmic events

They should feel:

- final
- distinct
- periodic

Do not visualize mining as coins being minted.

---

# 101. Transaction World Language

A transaction may be represented as:

- a structured proposal
- controlled packet
- channel transfer
- light structure moving between systems

Avoid flying coin animations.

The actual amount remains textual in precise UI.

---

# 102. Receive World Language

Receiving Bitcoin should feel like preparing an addressable channel.

The user creates a destination.

The world may represent this as:

- an open receiving conduit
- activated communication terminal
- stable receiving signal

Do not imply Bitcoin is already moving when only an address was generated.

---

# 103. Send World Language

Sending should have clear phases:

- preparation
- review
- authorization
- ready
- broadcast

The environment should distinguish them.

Do not visually send anything outward before broadcast actually occurs.

---

# 104. Broadcast World Language

Broadcast may be represented as a real outward transmission event.

Only after successful broadcast may the outgoing channel indicate completion.

Before that point, the transaction remains local.

---

# 105. Backup Is Not a Copy of Coins

The Archive must never imply Bitcoin itself is stored inside a backup capsule.

The backup represents:

> wallet recovery data

not:

> physical coins placed in storage.

Educational detail should make this explicit.

---

# 106. Key Is Not Bitcoin

Likewise, the key artefact represents signing authority.

It does not contain bitcoin.

The Vault does not literally contain coins either.

The world simplifies relationships while the Library exposes the technical truth.

---

# 107. Vault Is Not Custodian

The Vault metaphor must not imply Core Vault itself takes custody.

Core Vault is an interface.

Bitcoin ownership ultimately depends on valid cryptographic keys and Bitcoin's consensus system.

This must remain clear in educational layers.

---

# 108. No Bank-Like Institutional Language

Avoid environmental metaphors such as:

- teller counter
- bank branch
- account manager
- deposit desk
- approval officer

Core Vault should visually communicate self-custody.

---

# 109. No Military Security Aesthetic

Avoid:

- bunkers
- armed security
- biometric scanners everywhere
- warning stripes
- military blast doors
- tactical interfaces

Security should feel calm and precise, not paranoid.

---

# 110. No Corporate Lab Aesthetic

Avoid:

- office furniture
- conference-room glass
- fluorescent lighting
- corporate signage
- employee spaces
- open office layouts

The facility is personal, not organizational.

---

# 111. No Cyberpunk

Explicitly avoid:

- dark alley aesthetic
- purple neon
- excessive holograms
- rain-on-glass sci-fi
- glitch effects
- dense data overlays
- dystopian city imagery

Core Vault is technologically advanced without being cyberpunk.

---

# 112. No Steampunk

Bronze does not imply steampunk.

Avoid:

- exposed decorative gears everywhere
- Victorian machinery
- steam pipes
- gauges
- brass goggles aesthetic

Bronze is used with modern precision.

---

# 113. No Fantasy

Vaults, keys, and arches must not drift toward fantasy RPG visual language.

Avoid:

- runes
- magical crystals
- glowing swords
- mystical symbols
- enchanted artefacts
- castle aesthetics

The world remains grounded.

---

# 114. No Crypto Casino

Explicitly avoid:

- token icons
- market tickers
- green/red trading lights
- “bull market” imagery
- gold coin piles
- rockets
- moon imagery
- trading terminals

Core Vault is not part of speculative crypto culture.

---

# 115. Technological Sophistication Comes From Restraint

A sophisticated machine does not need hundreds of moving components.

A few beautifully designed mechanisms with clear state are preferable.

The environment should suggest:

> highly advanced technology that has become calm and mature.

Not:

> technology desperate to look futuristic.

---

# 116. Relationship to Reference Artwork

Images supplied from previous Bitcoin Core articles define the visual lineage of Core Vault.

They may influence:

- materials
- architectural mood
- lighting
- energy language
- object design
- composition
- atmosphere

They must not be:

- copied as production backgrounds
- treated as exact floorplans
- used as complete scene assets
- directly overlaid with application UI

The goal is to build **new original Core Vault spaces in the same visual family**.

---

# 117. Visual Lineage Test

A new Core Vault scene should satisfy two conditions simultaneously.

First:

> Someone familiar with the reference artwork should recognize the same design DNA.

Second:

> They should not think the scene is simply one of the reference illustrations reused.

That distinction is important.

---

# 118. World Consistency Test

When evaluating a new artefact or environment, ask:

> Could this object plausibly exist in the same facility as the Core Reactor, the Workshop, and the Archive?

If not, redesign it.

---

# 119. Semantic Test

Ask:

> What real Bitcoin or application concept does this object represent?

If the answer is unclear and the object appears interactive, it should probably not exist.

---

# 120. Atmosphere Test

Ask:

> Does this environment make careful Bitcoin operation feel calmer and more understandable?

If the environment primarily makes the product more exciting, it may be going in the wrong direction.

---

# 121. Physicality Test

Ask:

> Does this object appear to have material, mass, scale, and a believable place in the room?

If it looks like a floating UI icon, it does not belong to the primary world layer.

---

# 122. Technology Test

Ask:

> Does this feel advanced because it is precise and integrated, or because it glows everywhere?

Prefer precision.

---

# 123. Mediterranean Test

Ask:

> Does this feel Mediterranean through architecture, material, light, and relationship to landscape?

Not:

> Did we add a few arches and an ocean wallpaper?

Mediterranean identity must be structural.

---

# 124. Game-Like Test

Ask:

> Does this feel like a place I could inhabit in a high-quality game?

Then immediately ask:

> Does it still behave like serious Bitcoin software rather than a game?

Both must be true.

---

# 125. Facility Coherence Test

A user should eventually understand approximately where major functions exist without consulting a navigation menu.

If rooms feel spatially unrelated, the world design has failed.

---

# 126. Quietness Test

Take a room at rest.

Remove all active tasks.

Does it still feel complete?

If it requires constant animation, labels, notifications, or effects to stay interesting, simplify and strengthen the underlying design.

---

# 127. World as Interface Test

Remove permanent web UI.

Can the user still identify:

- important object
- navigable exits
- broad room purpose
- current semantic state

from the world itself?

If not, the environment is not carrying enough interface responsibility.

---

# 128. Final World Rule

The world of Core Vault should feel like:

> **A private Mediterranean Bitcoin facility built around precision, permanence, self-custody, and quiet technological power.**

It is not a theme applied to software.

It is the spatial language through which the software becomes understandable.

The stone gives the world permanence.

The sea gives it horizon.

The glass gives it transparency.

The bronze gives it physical precision.

The blue energy gives it computation and flow.

The gold energy gives it validated authorization and completion.

The artefacts give Bitcoin concepts physical intuition.

And Bitcoin Core remains underneath it all as the real machine whose state gives the world meaning.
